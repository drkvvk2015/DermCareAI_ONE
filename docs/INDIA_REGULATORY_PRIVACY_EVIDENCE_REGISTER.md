# India Regulatory / Privacy Evidence Register

This is a preparation checklist for formal accountable review. It is not a legal opinion,
regulatory classification, approval, certification, or clinical authorization.

| Evidence area | Required artifact | Status |
|---|---|---|
| Intended use and claims | controlled product/clinical claims statement | OUTSTANDING |
| Software function inventory | module-by-module function and clinical impact register | ENGINEERING PACKAGE |
| Risk management | hazard/risk analysis with mitigations | OUTSTANDING |
| Clinical evidence | validation package and accountable clinical sign-off | OUTSTANDING |
| AI-specific evidence | model provenance, validation, monitoring and change control | OUTSTANDING |
| Regulatory classification | formal assessment by qualified regulatory owner | OUTSTANDING |
| Data protection/privacy | clinic-specific lawful basis, notice, consent, retention and rights assessment | OUTSTANDING |
| Security controls | authentication, RBAC, tenant isolation, audit and secret-management evidence | ENGINEERING PACKAGE |
| Vendor/subprocessor review | cloud, messaging, payments, storage and AI vendors | OUTSTANDING |
| Production environment | infrastructure, backups, DR, monitoring and rollback evidence | OUTSTANDING |
| Accountable release approval | named responsible reviewer and date | OUTSTANDING |

## Required review package

Before a real clinical deployment, assemble:

1. Current product build/commit and artifact digest.
2. Intended-use and claims statement.
3. Software architecture and data-flow diagrams.
4. Risk-management file.
5. AI validation evidence register and results.
6. Security/privacy control evidence.
7. Production deployment/rollback evidence.
8. Clinic/operator/pharmacy workflow and accountability records.
9. Formal regulatory/privacy determinations from the responsible qualified reviewers.

No repository automation may convert these outstanding fields into an approval state without the
underlying evidence and accountable human decision.
